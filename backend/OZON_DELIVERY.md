# Бесплатные пробники и Ozon Доставка

Страница `/prob` показывает товары из Google Sheets с карточками из Seller API.
`/probs` перенаправляет на неё. Пробник и доставка для покупателя стоят 0 ₽,
эквайринг не вызывается. Один пробник на аккаунт обеспечивается уникальным
`Order.probeUserId` в PostgreSQL, включая параллельное оформление.

## Настройки

Docker Compose читает корневой `.env`. Для работы нужны:

- `OZON_CLIENT_ID`, `OZON_CLIENT_SECRET` — частное приложение Ozon Доставки.
- Доступы: `delivery-api.delivery`, `delivery-api.delivery-point`,
  `delivery-api.order`, `delivery-api.posting`.
- `OZON_DELIVERY_SHIPMENT_METHOD_ID=1020005036837360` — проверенный активный
  способ отгрузки «BAGINI — Москва, Складочная 1с5».
- `OZON_SELLER_CLIENT_ID`, `OZON_SELLER_API_KEY` — карточки товаров.
- `SHEET_URL`, `SHEET_SCRIPT_TOKEN` — остатки и атомарное резервирование пробников.
- Рабочие PostgreSQL и Redis.

Получатель должен быть зарегистрирован в Ozon с номером своего аккаунта магазина.
Перед оформлением сервер проверяет номер и доступность выбранного ПВЗ.
Доставку оплачивает отправитель с баланса Ozon Доставки. Посылку нужно физически
собрать и передать Ozon по настроенному способу отгрузки.

Габариты по умолчанию: 150 × 100 × 50 мм, 100 г, объявленная стоимость 1 ₽.
При необходимости задайте `PROBE_LENGTH_MM`, `PROBE_WIDTH_MM`, `PROBE_HEIGHT_MM`,
`PROBE_WEIGHT_G`, `PROBE_DECLARED_VALUE`. Объявленная стоимость — страховочная
оценка, покупателю она не начисляется.

## Применение изменений

Новая миграция обязательна: Ozon использует int64, и реальный ID способа отгрузки
не помещается в PostgreSQL INTEGER. Миграция также добавляет сохранённый запрос
для безопасного восстановления после таймаута.

Из корня проекта на сервере:

```sh
docker compose build backend frontend
docker compose run --rm --no-deps backend npx prisma migrate deploy
docker compose up -d backend frontend
docker compose logs --tail=100 backend
```

После запуска сервер в фоне загружает справочник ПВЗ. Первое наполнение может
занять несколько минут. Сообщение «Пункты выдачи Ozon обновлены» означает, что
обход завершён; затем справочник обновляется раз в сутки. При ошибке неполный
обход не помечается завершённым, а прежние ПВЗ не закрываются.

При локальном запуске Nest не загружает корневой `.env` автоматически.
Передайте переменные окружения процессу, например из каталога backend:
`node --env-file=../.env dist/src/main.js`.
Адреса `postgres` и `redis` в корневом `.env` предназначены для Docker-сети.

## Статусы и сбои

`posting/approve` работает асинхронно: до подтверждения готовности к отгрузке
заказ остаётся `pending` и оплаты не требует. Статус обновляется при открытии
страницы заказа или страницы пробников. После таймаута создания повторяется
сохранённый запрос с прежним UUID, без второго списания остатка.

При определённой ошибке оформления и успешной отмене отправления резерв и лимит
аккаунта освобождаются. Пока отмена не подтверждена, они сохраняются: это защищает
от второго пробника при уже существующем отправлении. Если резервирование в
Google Sheets либо запись результата резерва в БД прерваны, заказ и остаток
нужно сверить вручную; таблица и PostgreSQL не поддерживают общую транзакцию.

Проверки 13 ноября 2026: OAuth и все четыре доступа работают; собранный сервис
возвращает 9 бесплатных пробников; расчёт заказа — 0 ₽; список и сведения о ПВЗ
доступны; проверенный ПВЗ принимает посылку с указанными габаритами.
Реальные заказы и платные отправления при проверке не создавались.
